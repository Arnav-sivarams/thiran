# Initial semantic contract (TH-001)

**Design only.** This freezes the minimum choices needed to guide TH-004 through TH-008; it is not a complete 1.0 specification or current parser syntax. Examples are preferred source notation, subject to grammar review without changing their meaning. No new parser, checker, or runtime is implemented here.

## Values, types, and inference

Thiran is statically typed. Locals infer types from initializers; every function parameter is annotated, while private acyclic function results may be inferred. Public functions, exported values, FFI declarations, and recursive functions require explicit parameter/result types. Type inference cannot promote an already typed numeric value implicitly. Generic functions may parameterize over scalar types and compile-time rank/size constants with declared constraints; their exact surface grammar and trait vocabulary belong to TH-005. Monomorphization must preserve the same semantics, with diagnostic/code-size limits rather than hidden behavioral specialization.

The initial scalar set is `bool`, `i32`, `i64`, `u32`, `u64`, `f32`, and `f64`. Unsigned types serve bit-oriented data and external formats; they are not default mathematical integers. Integer literals default to `i64` when unconstrained, real literals to `f64`. An untyped integer literal adopts a contextual dtype only when exactly representable. An untyped real literal adopts a contextual `f32` or `f64` dtype by one specified round-to-nearest-even conversion of its mathematical decimal value; unconstrained real literals use `f64` by that rule. This is literal typing, not promotion or narrowing of an already typed value: `0.1` can be used in an `f32` model without a cast, while an `f64` variable cannot silently narrow to `f32`. Literal conversion must be backend-independent and conformance-tested. Strings are immutable UTF-8 values for paths, messages, and data labels; there is no implicit byte/character indexing contract in V0. Tuples are ordered heterogeneous values, records/structs have named fields and value semantics, and functions have typed parameter/result signatures. There is no class hierarchy or implicit subtyping. An immutable scalar and a rank-0 tensor are distinct types; scalar operations do not secretly allocate tensors.

`Tensor<T, R>` is a numeric/bool tensor logical value with **compile-time rank** `R >= 0` and runtime nonnegative `i64` extents. Its storage may be independently owned or shared read-only between immutable value handles; the source type does not expose physical uniqueness. Tensor element type is a scalar dtype, never a record or string in V0. A tensor may reside on CPU or device; placement is a checked runtime property, not a silent change in its mathematical type. Shape constraints on public boundaries are runtime-checked contracts unless a dimension is a compile-time constant. Rank-polymorphic generics handle known-at-specialization rank; a dynamically ranked existential tensor, with explicit rank inspection before rank-specific operations, is required for genuinely data-dependent ingestion before the full dataset workflow can be claimed (TH-008), but not for the first fixed-rank native slice. `Buffer<T>` is the separate CPU-addressable collection for records and bytes, not an alternative numerical tensor API; its alias and mutation rules match owned storage. It is not silently converted into a tensor. Numeric rectangular bracket literals create tensors, including a one-row vector `[1, 2]`; general buffers use explicit constructors. This distinction preserves concise mathematics and general systems storage.

Compile-time constants are immutable values known during checking and may supply rank, size, and configuration; evaluation must be bounded and effect-free. `const` declarations cannot read files, RNG, or devices. Type and rank parameters are part of public API compatibility. Numeric casts are explicit and checked when a value might not fit; `as`-style unchecked truncation is not the default. Already typed mixed dtypes have **no implicit promotion**, including tensor/scalar mixes; untyped literals follow the contextual rules above. Explicit `cast` defines rounding/saturation/overflow mode. This avoids backend-dependent promotion tables and silent storage/device changes.

Default integer arithmetic checks overflow and integer division by zero; an invalid operation fails at the documented checked precondition. Explicit wrapping/saturating/checked-result operations belong in the standard library. Default floating arithmetic uses IEEE-754 round-to-nearest-even at the declared dtype, preserving signed zero, infinities, and NaNs. Floating division by zero follows IEEE behavior. `f16`, `bf16`, complex values, and mixed-precision accumulation are staged after the first numerical slice (TH-008). Strict floating semantics disallow silent fast-math reassociation; reduction and matrix-kernel rounding envelopes must be fixed and conformance-tested before a native backend claims equivalence (TH-008). An explicit relaxed profile may permit additional transformations, with its effects recorded in artifacts.

## Tensor shape, layout, and operations

Rank is a type property; extents are values. Every tensor has a logical row-major index space. Physical storage has layout and strides; contiguous row-major storage is the default for new literals and operation results, while read views may have legal strided layouts. The initial positive-step slice and transpose operations require positive strides; negative-stride views are deferred. A backend that cannot preserve a legal view contract must reject that lowering rather than silently copy or create a writable alias. Logical semantics never depend on layout. Device transfer is explicit and effectful. Shape/rank mismatch is a checked failure, not implicit truncation. Zero-sized axes are valid.

Indexing is **zero-based**. An integer index must satisfy `0 <= i < extent`; negative indices are rejected. A range `start:end` is **half-open** with `0 <= start <= end <= extent`. Optional `:step` requires a positive nonzero step in V0. Omitted bounds mean `0` and `extent`; no wraparound, ellipsis, or implicit last-element shorthand is frozen. `A[i, j]` returns a scalar when all axes are indexed. A mixed index/slice returns a borrowed view with indexed axes removed; `A[:, j]` is therefore rank one. Bounds checks apply in CPU, GPU, interactive, and deployment modes. `get(A, indices)` returns `Option` for out-of-bounds access; ordinary invalid `A[...]` fails predictably.

The preferred notation remains `A * B` for **rank-2 matrix multiplication** and `A .* B` for elementwise multiplication. `A * scalar` and `scalar * A` scale tensor elements. Two tensor operands of other ranks cannot use `*`; named `dot`, `batched_matmul`, or `contract` operations carry their own contracts. `+` and `-` on tensors are elementwise; `./` is elementwise division. Tensor/tensor `/` does not mean matrix solve and is rejected. Unary `-` and comparisons act elementwise where defined. Operators on tensor operands produce new logical value results and never mutate an operand. This uses mathematical shorthand without adopting MATLAB's one-based or matrix-division rules.

Elementwise binary operations broadcast **trailing axes**: align ranks from the right; per axis, equal extents or one extent of `1` is legal, and the result takes the other extent (including `0` with `1` yielding `0`). Other pairs fail. A scalar broadcasts as a rank-0 value, without allocating a tensor. Broadcasting is logical read expansion, never a writable overlapping view. The result rank is the maximum operand rank. Conformance tests must cover `0`, `1`, and mismatched extents.

`[1, 2; 3, 4]` is the preferred rank-2 tensor literal: commas separate columns, semicolons separate rows, all rows must be rectangular, and elements must share one dtype after contextual literal typing. `let A = ...` declares the binding; `A = ...` is rebinding of an existing mutable binding, not declaration. There is no implicit concatenation from adjacent brackets or whitespace. Literal rank beyond two uses explicit constructors.

Slicing returns a **borrowed read view**, not a copy. Its conceptual type is `TensorView<T,R>` with a lifetime tied to a live source value handle; `TensorViewMut<T,R>` requires exclusive mutable access to unique live storage. A view is not an independent immutable alias: it cannot outlive the handle from which it was created or be returned from a local handle. The first slice model does not accept multiple independently writable overlapping views. `transpose(A)`/`A.T` is a read view with swapped axes for rank two. Conjugate transpose is explicitly `adjoint(A)`/`A.H`; for the initial real dtypes it has the same values as transpose, while later complex dtypes conjugate. Apostrophe transpose syntax is not adopted. `reshape_view(A, dims)` yields a read view only when a legal contiguous reinterpretation exists; otherwise it fails. `reshape_copy(A, dims)` explicitly returns independent storage and checks equal element count. `copy(A)` performs a deep copy to independent storage. `concat(axis, tensors)` and tensor arithmetic return new logical values; reductions return a reduced tensor value or scalar as dictated by declared axes and rank; `matmul` returns a new logical value. New value-producing arithmetic never mutates an operand. Storage allocation or reuse is a lowering choice only if logical values, observable mutation, effects, and numerical results are unchanged. These contracts distinguish views from copying and make expensive paths visible.

For `matmul`, rank-2 shapes `(m, k) * (k, n)` yield `(m, n)` with equal input dtypes; incompatible inner extents fail, and no operand is implicitly transposed. `concat(axis, inputs)` requires equal rank/dtype and equal non-concatenated extents; the selected extent is the checked sum. Reduction axes are zero-based and explicit. Initial `sum(A, axis)` drops that axis, returning a scalar for rank-one input; an empty summed axis yields additive zero, integer accumulation checks overflow, and floating accumulation obeys its published numeric envelope. Initial `mean(A, axis)` on an empty axis fails its checked precondition. Any `keepdims` variant is named/explicit and retains a length-one axis. This leaves reduction rounding strategy to TH-008 without leaving result shape or empty-input behavior ambiguous.

## Bindings, borrowing, and mutation

`let x = expression` creates an immutable lexical binding; `let mut x = expression` allows rebinding and requests exclusive mutation. Immutable scalars copy on use. Ordinary binding of a tensor, buffer, or record containing one creates another **read-only logical value alias** without invalidating the source and without a deep copy: `let A = [1, 2; 3, 4]; let B = A; let C = A + B` is valid. `copy(A)` explicitly creates independent storage; `move(A)` explicitly consumes the source binding and transfers its value handle. A compiler may implement a non-consuming alias as a physical transfer when the source is dead afterward; this is unobservable. An explicit move of a handle does not make shared storage unique if other aliases survive. No hidden copy-on-write allocation is permitted to make mutation appear to work. Rebinding `x = expression` replaces the bound value and never modifies previously visible storage. Indexed assignment or in-place operation mutates storage only through exclusive access from a mutable binding. The checker rejects mutation while another potentially live alias, view, AD save, or asynchronous use of the same storage exists; after its last use, exclusive access may be statically justified. `let mut A = ...; let B = A; A[0, 0] = 7; print(B)` is rejected; `let mut A = copy(B)` creates independent storage and can be mutated. Tensor expressions such as `x + y` are value-producing, never destructive updates. Mutation visible across a function boundary is represented by mutable access or an explicitly returned new value/state, not a hidden alias.

Ordinary read use, including a read-only tensor parameter, needs no visible `borrow` at the call site. The typed IR still records a shared read use and its lifetime. Explicit mutable access (`borrow mut` as provisional spelling) requires a mutable binding and exclusive live storage; explicit consuming access (`move` as provisional spelling) invalidates its source binding. Shared reads and mutable accesses to the same live storage cannot overlap. Borrowed views cannot outlive their originating live handle, be returned from a local handle, or remain live across its explicit move. Immutable aliases are independent logical value handles, not views, and may survive the original binding. The checker must reject conflicting aliases across tuples, records, closures, calls, AD saves, and device events, not just variable names. The first safe subset does not require proof of disjoint mutable subviews; a future disjointness API may provide checked splitting. Where uniqueness cannot be statically justified, mutation is rejected, not rescued by runtime copying.

AD may retain saved intermediates through a gradient computation; mutation of required shared storage before its last saved use is rejected or needs an explicit snapshot/recompute contract. An explicit move may transfer a value handle only while preserving any outstanding saved-value lifetime; it does not waive an AD reservation. GPU operations may complete asynchronously, but shared storage and exclusive-access reservations remain live through the completion event; user-visible scope exit must wait, transfer an event-retained handle, or report a checked error. Safe source never frees or reuses live storage. Unsafe FFI/raw-pointer code must declare alias, extent, lifetime, thread/device, and ownership-transfer contracts; a consuming FFI operation requiring unique physical storage must be statically justified or use explicit independent storage. Safe wrappers validate what they can and isolate uncheckable assumptions inside `unsafe`. Runtime handle counting may be necessary for escaping shared values, especially asynchronous and FFI boundaries; proven single-owner paths may erase it. The language does not promise zero bookkeeping in all cases. This is a design safety subset, not implemented proof.

## Functions, results, and control flow

Preferred declarations are `fn normalize(x: Tensor<f32, 2>) -> Tensor<f32, 2> { ... }` and `export fn ...` for public functions. An unmarked tensor or buffer parameter receives a non-consuming read-only value handle by default; its call needs no visible borrow syntax. The typed IR records its read access, alias/lifetime behavior, and any returned logical value that retains storage. `mut`/`borrow mut` marks exceptional exclusive mutable access; `move`/`own` marks consuming access, with exact spelling deferred to grammar review. Neither is inferred from a public signature. A normal return is a value; multiple results use tuples, e.g. `return (output, next_state)`. A function may return a borrowed view only when its signature explicitly ties the view lifetime to a caller-owned parameter, never to local storage. Returning a tensor logical value may retain storage from a read-only parameter without copying; this is an alias-valued result, not a borrowed view. Local bindings infer types. Recursive runtime functions are permitted with explicit signatures and termination/resource behavior left to the program; compilation may inline when legal but cannot require universal compile-time expansion. Private first-slice functions need no closures or function values. Higher-order functions and checked lexical closures are included in the language direction but deferred to TH-005; captures must state move/read/mutable behavior and respect the same safety rules.

`if condition { ... } else { ... }` requires a scalar `bool`; a tensor mask requires explicit selection such as `where(mask, a, b)`. Branches must produce compatible result types. `for i in 0:n { ... }` iterates a zero-based half-open range; `for row in A { ... }` iterates read views of leading-axis slices, with lifetime tied to `A`. Mutation during that read iteration requires a separate checked exclusive form or indexed loop. `while condition`, `break`, and `continue` are supported as structured control flow; the condition is scalar `bool`. Conditions depending on tensor values require explicit scalar reductions or extraction, with any host/device synchronization represented as an effect. Loops and branches are not flattened into the existing pure tensor Graph. Differentiation of structured control flow follows the executed path and iteration count under the AD contract; a nondifferentiable branch condition is not silently differentiated.

## Errors, modules, and packages

Compiler errors are spanned diagnostics with stable categories, relevant types/shapes, and actionable explanations. Distinguish: (1) statically rejected typing, rank, ownership, effect, or provably invalid bounds/shape/constant arithmetic contracts; (2) checked runtime contract failure when bounds, shape mismatch, integer overflow/division by zero, or explicit preconditions depend on runtime values; (3) typed `Result<T,E>`/`Option<T>` alternatives for recoverable handling; and (4) resource/runtime failures, such as allocation or device loss, which are not mislabeled programming-contract violations. Ordinary checked operations may terminate with a clear contract diagnostic; `get`, checked-arithmetic, and `try_*` shape/operation APIs offer recoverable alternatives. File, parse, device transfer/observation, checkpoint, allocation-sensitive `try_*` operations, and user validation use typed results; exact propagation spelling and error taxonomy are staged. An ordinary allocating operation may report resource failure and terminate if no recovery API was selected, but safe code never turns it into undefined memory behavior. No implicit exceptions are required. Asynchronous GPU failure is delivered at synchronization/observation through an error-bearing contract; an unobserved failure cannot silently produce a valid-looking result.

One `.th` file is one module. Explicit `import "relative.th" as alias` and qualified `alias.name` preserve useful R12 spelling; `export` defines the public API. Imports are resolved from the importing file and cannot escape the local project boundary without a declared dependency. Private symbols stay private; no wildcard import or implicit global search path. Modules may have ordinary top-level declarations and initialization governed by effect rules rather than flattening every file into one Graph. A future project manifest declares package identity, dependencies with semantic version constraints, lock resolution, and local projects; package registry/network retrieval are deferred to TH-009. The standard library occupies explicit namespaces. Public function types, ownership modes, effects, and shape preconditions are part of compatibility.

## Semantic boundary to AD, state, and execution

Differentiation is an explicit request on eligible typed functions, not a hidden global tape. Reverse mode is required for training; forward mode is a later, compatible extension. A gradient result is a logical value with retained storage or carries an explicit caller lifetime for a borrowed view; it cannot expose an untracked physical buffer. Saved values and recomputation are compiler choices only when they preserve mutation, RNG, state, and numerical contracts. A custom derivative must declare primal/derivative types, saved values, effects, and supported backend behavior. Nondifferentiable values and operations produce a diagnostic unless explicitly stopped by `stop_gradient`/`no_grad` semantics; gradients through mutation need defined versioning or rejection. Stateful model functions take explicit state and return `(output, next_state)`; reset, prefill, step, chunk, and checkpoint APIs are ordinary library contracts, not model-specific syntax. Pure computation, mutation, RNG, I/O, host/device transfer, persistent state, and asynchronous work have distinct IR effects even before full surface effect syntax exists.
