# TH-005 typed structured semantic IR (developer checkpoint)

This is an internal, non-stable IR for the bounded TH-004/TH-005C V0 syntax subset. Frozen language semantics govern it; syntax spelling is not the authority. The pipeline is `source -> spanned syntax AST -> semantic analyzer -> typed structured semantic IR -> independent verifier -> exact C++ reference evaluator`. No V0 operation is lowered to R12 Graph, Node, RegionPlan, or BackendIR here. [CONTROL_FLOW_V0.md](CONTROL_FLOW_V0.md) specifies the TH-005C extension.

**syntax AST != semantic IR. semantic IR != Graph IR. semantic reference evaluator != production runtime. semantic success != memory safety. semantic success != native execution.**

## Semantic types and support layers

The IR represents `bool`, `i32`, `i64`, `u32`, `u64`, `f32`, `f64`, `Tensor<T,R>`, `Buffer<T>`, and ordered heterogeneous tuples. `u8` is recognized as a byte element for `Buffer<u8>`, matching the frozen byte-buffer examples; it is not a TH-005 tensor numerical dtype. Tensor element T is an accepted scalar dtype; rank R is an integer from 0 to 32. Tensor rank is in the type, but extents are not. Buffer is distinct from Tensor. A recognized type is not proof its operations or reference execution exist. The executable subset is i64, bool, Tensor<i64,1/2>, and tuples of executable values. Arithmetic is exact i64 only. Other scalar/tensor types may be resolved in signatures but numerical operations are diagnosed as unsupported.

Literal decimal spelling is parsed by checked magnitude accumulation. The default unconstrained integer dtype is i64. The narrow V0 rule for spelling I64_MIN is that unary `-` directly applied to a decimal integer token may consume magnitude `9223372036854775808` and yield `-9223372036854775808`; an unsigned/positive token of that magnitude is invalid. Any larger magnitude is invalid. This is literal typing, not a signed host overflow. Real expressions remain unsupported by TH-004. Contextual non-i64 literal conversion is not claimed in this executable subset.

## Module, functions, blocks, identity

The module retains source identity, imports, ordered function declarations, and an ordered internal top-level initializer block for current pure `let` items. That initializer is not a public function. Imports are parsed but a module containing them receives `TH005-IMPORT-STAGE`; no cross-file linking or qualified global fallback is claimed. Future top-level effects and module resolution remain open.

FunctionId starts at 1 in deterministic declaration order. ValueIds start at 1 per function, parameters first and instructions in deterministic expression/evaluation order across nested blocks. BindingIds and BlockIds also start at 1 per function. IDs are not addresses. Function calls remain `Call` instructions with callee FunctionId; no inlining/Graph expansion occurs. Blocks have ordered instruction/check/binding/control steps, binding facts, and structural completion. Nested blocks carry identity and parent BlockId, not raw parent pointers. Instructions and control steps retain SourceSpan. The dump is deterministic, developer-only, and neither a public serialization format nor a compatibility promise. It omits the module source-name field so caller-supplied absolute machine paths cannot enter the dump; diagnostics still retain that source identity.

Every parameter has a semantic type and an access-mode field (`ReadOnly`, `ExclusiveMutable`, `Consuming`); the current parser supplies `ReadOnly`. Result types are explicit for exports/recursive functions. Private acyclic omitted results are inferred by declaration collection and deterministic dependency-triggered analysis. An inference cycle requires explicit signatures. A bounded call-depth guard applies during reference execution; recursive runtime functions are not forbidden when explicitly typed.

## Bindings, values, views, shape facts

`let` introduces a lexical BindingId, `let mut` introduces a rebindable one, and `x = expression` updates its current logical value with exactly the same semantic type. Duplicate same-block declarations, undefined names, immutable rebinds, and type-changing rebinds fail during analysis. Identifier use emits `LoadBinding` to produce a fresh expression ValueId from the binding's current logical value. `let B = A` creates a distinct BindingId but emits neither Copy nor Move and does not consume A; both bindings initially denote the same logical value. `BindingWrite` is a source binding transition, not a physical store. Branches and loops need no analysis-time chosen ValueId or hidden buffer join. TH-006 must attach storage alias/lifetime and exclusive-access rules; TH-005C claims no ownership proof.

A tensor ValueId has a ShapeFact vector with one slot per rank axis, each a known nonnegative extent or `?`. Literal `[1,2;3,4]` has `Tensor<i64,2>` and `[2,2]`; a parameter `Tensor<i64,2>` has `[?,?]`. Known facts are used to distinguish proof from required runtime checks. Logical indexing and flat row-major observation are semantic; layout, strides, allocation, handle sharing, and buffer reuse are not IR facts here. Slice, partial indexing that leaves a tensor, and rank-2 `.T` instructions carry `borrowedView=true`; the evaluator materializes values for observation only and does not validate view lifetimes or promise a physical copy implementation.

## Core operations and explicit checks

Core instruction kinds cover literals, tuple, unary negation, i64 arithmetic, elementwise operations, rank-2 matmul, index/slice, transpose, sum, and calls. No neural-model operation enum is introduced. `+`, `-`, `.*` broadcast trailing axes with equal-or-one extents, including zero with one. `*` scales a tensor with a scalar and is matrix multiplication for two rank-2 tensors; other tensor/tensor ranks fail typing. Products and accumulation are checked i64. Indexing is zero-based, nonnegative, and removes integer-selected axes. Slicing is half-open, positive-step, retains slice-selected axes, and yields a logical read view. `.T` swaps rank-2 shape facts and is a read view. `sum(A,axis)` drops the axis, returns scalar at rank one, returns additive zero for an empty summed axis, and checks every accumulation. In TH-005 its axis must be a compile-time constant because a dynamic axis would make the result rank indeterminate; dynamic axes are diagnosed `TH005-DYNAMIC-AXIS`.

When facts prove a bounds, broadcast, matmul inner-dimension, or slice condition invalid, analysis reports the violation statically. When facts prove it valid, no redundant check is required. When proof is incomplete, an ordered `Check` step names its kind, operands/selector metadata, SourceSpan, and semantic failure ID. Its `CheckedFailure` effect is observable and must not be erased by later lowering. Arithmetic/index/slice/sum/call instructions also carry checked-failure effect metadata where their operation may trap; ordinary value production is otherwise pure. Future classifications have placeholders for mutation, RNG, I/O, transfer, and async, without claiming a complete effect system. The exact-i64 conformance failure IDs are `TH-SPEC-I64-OVERFLOW`, `TH-SPEC-BOUNDS`, `TH-SPEC-SHAPE`, `TH-SPEC-BROADCAST`, `TH-SPEC-SLICE`, and `TH-SPEC-AXIS`. Static and runtime detection can normalize to the same fixture ID. Other `TH005-*` categories are internal and not stable public diagnostic IDs.

## Verifier and reference evaluator

The verifier is independent of the analyzer and checks unique/monotonic semantic IDs, valid types, tensor shape-fact rank, region-local operand visibility/use-before-definition, binding declaration/rebind contracts, nested block identity/parentage, loop legality, condition/bound types, instruction/call/check contracts, Return types, and structural completion. Manual malformed straight-line and CFV01–CFV10 structured IR tests exercise these checks without invoking the analyzer. Analyzer success is not substituted for verifier correctness.

The C++ standard-library reference evaluator first verifies IR, then executes the initializer or a named function using distinct i64, bool, tensor, and tuple runtime values. A tensor carries dtype, nonnegative runtime shape, and flat logical row-major elements. Checked overflow is established before any invalid signed operation, including unary negation, scalar/elementwise arithmetic, matmul products and accumulation, and sum. Runtime Check steps execute with their declared semantic ID. A call-depth and step/tensor-size limit prevents accidental unbounded execution; resource-limit IDs are evaluator-internal, not conformance IDs. Observation formatting is deterministic and adapts scalar/tensor success to the TH-003 status/kind/dtype/value-or-shape/values core, or checked failure to status/error_id. Tuple observation is a developer extension, not part of the TH-003 fixture schema. This evaluator is neither Python-dependent nor optimized/native production execution.

## Intentionally unsupported

No ownership/borrow/view-lifetime proof, physical storage, real or non-i64 arithmetic, generic function specialization, native CPU/GPU, AD, AOT/JIT, package linking, or production CLI routing exists here. Iterable-tensor `for` is parser-only and receives `TH005C-ITERABLE-FOR-DEFERRED` in semantic analysis. `/` and `./` parse but exact integer division rounding is not fully fixed by the frozen subset, so analysis reports `TH005-DIVISION-UNSPECIFIED` instead of inventing a rule. Unsupported members other than rank-2 i64 `.T` are diagnosed. Import-containing modules are deferred, not silently linked. The source grammar cannot construct an empty tensor literal; a zero-sized runtime tensor reduction is tested through the direct evaluator call boundary.
