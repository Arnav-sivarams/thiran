## Defect and contract

`Graph::nodes` is a `vector<shared_ptr<Node>>` and owns nodes. `Graph::edges` and node input/output adjacency hold non-owning raw pointers. `Graph::removeNode` disconnects all incident edges, removes its symbol, and erases its owning vector position; it does not leave a null slot. The old `RewriteEngine` held a reference to a vector slot in a range loop while `RemoveDoubleReluRule` erased that vector position. Erasure compacted the vector, invalidating the traversal reference and causing the valid-program crash. The rule also reconnected consumers by appending their inputs, which could reverse operands of a noncommutative consumer.

Each rewrite round now snapshots owning node handles in `graph.nodes` vector order. Candidates are considered in that order, and rules in registration order. A candidate must still be a graph member before matching. A successful rewrite ends the round; the graph is verified, and a new round begins from the current vector order. Removed candidates never enter a later round. New nodes enter the next round, never the round that created them. Rule matches must be read-only, and `rewrite` must return true exactly when it changes the graph; false must leave it unchanged. The engine returns on a full no-change round (fixed point). It throws if a mutation fails graph verification or if more than 10,000 successful rewrites occur, so oscillating rule sets cannot loop forever. The limit is a defensive bound, not a proof of convergence for future rules.

`Graph::containsNode` compares ownership membership without dereferencing a removed pointer. `Graph::replaceInput` changes a producer while preserving the consumer input position and the graph edge position. It refuses a replacement that would collapse two operand slots into one unique producer/consumer edge. Double-ReLU and fusion check that collision before changing the graph. `GraphVerifier` now checks both directions of edge/adjacency correspondence, including output adjacency.

`prepareGraph` still runs canonicalization, constant folding, rewriting, fusion, DCE, then final verification. No language-design or native-execution capability was implemented.

### Defect, reproducer, and semantic invariant

ConstantFold chooses the input to an identity `Add(X, 0)` or `Multiply(X, 1)` (also applicable to redundant transpose, reshape, and transfer). Its original `replaceWithInput` copied the folded node's outputs and, for each consumer, called `graph.disconnect(folded, consumer)`, then `graph.connect(replacement, consumer)`. `connect` appends the producer to `consumer->inputs`. Thus `Subtract(Folded, Y)` changed to `Subtract(Y, X)` even though GraphVerifier still passed. A replacement whose producer already occupied another consumer slot instead lost an operand: `connect` refuses a duplicate producer/consumer edge after the old edge has already been disconnected, and the folded node was removed. Either failure silently changes meaning.

Before changing ConstantFold, `constantFoldSlotZero` constructed the minimal scalar graph `X, Zero=Constant(0), Folded=Add(X,Zero), Y, Subtract(Folded,Y), Output(Subtract)`. After `cmake --build /tmp/th002-debug-final --parallel 2 --target rewrite_regression_tests` (exit 0), `/tmp/th002-debug-final/rewrite_regression_tests` exited 1 with `Failure at line 232: subtract->inputs.size() == 2 && subtract->inputs[0] == x && subtract->inputs[1] == y`; the verifier nevertheless printed `Graph Verification : PASSED`. The expectation was not changed to accept the broken operand ordering.

Invariant: a legal replacement must preserve each consumer's exact input slot, the remaining edge order and adjacency, and any `Output` node's connectivity. If any consumer cannot represent the replacement under the unique-edge Graph model, the **entire fold** must decline before changing nodes, edges, adjacency, or output connectivity.

### Narrow repair and collision contract

`src/optimizer/ConstantFold.cpp` now preflights *all* consumers before mutation: membership, unique old input/output/edge correspondence, and absence of the replacement in the consumer's inputs, replacement's outputs, or graph edges to that consumer. Only after all consumers pass does it call the existing TH-002 `Graph::replaceInput` for each consumer, then remove the folded node. `replaceInput` retains the input slot and the existing edge position; graph removal deletes only the folded node's incident input edges. A failed preflight returns without changing the graph. An unexpected failure after a successful preflight raises a logic error rather than silently claiming a successful fold; on a valid single-threaded Graph the preflight matches the helper's refusal conditions. No Graph API or multi-edge representation change was made.

Collision regression: `Add(X, 0)` feeds both a legal subtraction and `Subtract(Folded, X)`, with the legal consumer visited first. Folding would require `Subtract(X, X)`, which the current unique-edge representation cannot encode. The whole fold declines; the test asserts the original graph signature, owning nodes, both subtraction slots, output identity, verifier success, and an unchanged second run. No earlier legal consumer is partly rewired.

Focused cases added to `RewriteRegressionTests`: T1 `Subtract(Folded,Y)` slot 0; T2 `Divide(Y,Folded)` slot 1; T3 two noncommutative consumers in opposite slots plus direct `Output(Folded)`; T4 all-or-nothing duplicate-producer refusal; T5 canonicalization → constant folding → double-ReLU rewriting → matmul/ReLU fusion → DCE → verification with `Subtract(Folded,Y)` and exact final `Subtract(FusedMatMulRelu,Y)` signature; T6 successful fold followed by an unchanged second ConstantFold run. Each legal case checks graph structure and verifier success, not merely node count. The existing TH-002 rewrite/fusion tests remain in the same executable.
