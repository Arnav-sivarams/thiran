# TH-013 — first native GPU backend

TH-013 introduces a device-neutral `TensorRegion` library shared by the accepted TH-008 CPU emitter and a new optional synchronous native GPU backend. The CUDA implementation is localized to `NativeGpu`: it dynamically loads the low-level CUDA Driver API, JIT-loads backend-owned PTX, manages RAII device allocations, launches checked kernels, synchronizes, and observes results. CUDA vocabulary does not enter parsing, typing, structured semantic IR, ownership analysis, or source semantics.

The implemented GPU region subset is contiguous offset-zero row-major rank-1/rank-2 i64/f32 tensor input/literal, immutable alias, equal-shape Negate/Add/Subtract/ElementMultiply, and full-rank Index where the current semantic frontend admits it. Multi-operation regions execute as sequential kernels. Signed i64 arithmetic preserves checked overflow. Unsupported dtype, rank, layout, broadcasting, matmul, reduction, view, call, mutation, structured control, and scan reject without fallback. Native CPU coverage is unchanged.

Host storage remains distinct from per-execution device storage. H2D and D2H boundaries are explicit and checked. Immutable aliases share allocation handles, repeated identical host storage is uploaded once per execution, explicit copies remain independent, and input allocations are never mutated. Zero-element tensors allocate and transfer no bytes and launch no kernel. Byte, element, and launch geometry arithmetic is checked.

The backend is disabled by default through `THIRAN_ENABLE_NATIVE_GPU=OFF`, preserving CPU-only builds. An enabled build needs only the host C++ toolchain plus dynamic-loader support; nvcc and CUDA headers are not required because this first adapter uses the Driver API and PTX. At runtime, missing driver, missing device, invalid selection, unsupported capability, module/kernel load, allocation, transfer, launch, and synchronization failures are explicit checked errors. No Python or ML framework participates in GPU execution.

The physical-GPU integration executable reports PASS only after device initialization, nonzero device allocation, H2D transfer, multiple kernel launches, synchronization, D2H observation, and comparison with Thiran reference results. It returns the registered CTest skip code when the driver/device is unavailable. Such a skip keeps CPU-only CI usable but does not qualify TH-013 as PASS.
