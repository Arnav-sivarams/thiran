## Architecture and legality

`source -> V0 parser -> typed semantic IR -> independent semantic verifier -> TH-006 ownership/effect analysis and fact audit -> TensorRegion extraction -> independent TensorRegion verifier -> generated C++20 -> host compiler -> native ELF -> canonical result`.

TensorRegion is a new V0 tensor/dataflow DAG, **not legacy Graph**, whole-program semantic IR, kernel IR, or buffer IR. It uses semantic ValueIds as deterministic node IDs and retains ordered inputs, one output, dependency edges, semantic type, shape facts, source spans, and attached Check metadata. The extraction gate accepts only an entirely supported straight-line function; supported MayTrap checks remain observable. Mutation/RNG/IO/Transfer/Async and all unsupported structured/operation forms fail `BACKEND-UNSUPPORTED`. Known valid semantic broadcasting fails as backend-incomplete, not `TH-SPEC-BROADCAST`. Unknown runtime unequal extents take a non-semantic backend-incomplete error path. STRICT_NATIVE contains no evaluator or framework fallback; **no fallback occurred in qualified native runs**. Coverage lists native nodes, unsupported operation qualification, and `fallback: NONE`.

The region verifier's manually built negative matrix is TRV01 duplicate ID, TRV02 unknown dependency, TRV03 use before definition, TRV04 invalid Add result, TRV05 Add input mismatch, TRV06 known Add shape mismatch, TRV07 invalid Index input, TRV08 non-i64 Index result, TRV09 missing output, and TRV10 unsupported admitted operation. It also validates literal element count/types and attached Check kind/ID. Repeated region dumps are identical.

The emitter is compact deterministic C++20 with ID-derived local names. Literal and Add result tensors use TH-007 `storage::Tensor::materializeI64` (contiguous row-major, offset zero, independent result storage). Immutable aliases copy a storage handle, not elements. Add checks equal concrete shapes, reads logical values, uses explicit pre-operation i64 overflow guards, and materializes a fresh result. Index rejects negative coordinates and uses TH-007 checked `loadI64`, never unchecked pointer arithmetic. Entry catches only supported `SemanticFailure` IDs (`TH-SPEC-BOUNDS`, `TH-SPEC-I64-OVERFLOW`) as canonical semantic errors; unknown `std::exception` is stderr plus nonzero internal failure. Generated C++ is lowering output, not Thiran source semantics. Bootstrap native AOT != production AOT; C++ backend != final backend architecture; native execution != optimized execution.
