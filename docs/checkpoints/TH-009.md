## Developer toolchain architecture

The reusable `thiran_v0_tooling` driver composes, without duplicating, `source bytes -> parser -> semantic analyzer -> semantic verifier -> ownership/effect analysis -> ownership fact audit -> STRICT_NATIVE TensorRegion extraction -> deterministic C++20 emitter -> configured host compiler -> native process`. Structured results retain stage, diagnostics, coverage, generated text, artifact path, build record, and subprocess exit/stdout/stderr. Absolute source paths remain diagnostic identity and never enter TensorRegion or generated-source identity.

`CompilerStage` distinguishes input, syntax, semantic, semantic-verifier, ownership/effect, backend, host compiler, artifact execution, and internal-tool failures. `checkSource` ends after ownership audit and therefore accepts valid programs outside native coverage. MatMul passes check but fails build as `BACKEND-UNSUPPORTED`, records `MatMul unsupported-native`, and retains `fallback: NONE`.

The separate, uninstalled `thiran-v0` executable implements `check`, `emit-region`, `emit-cpp`, `build`, and `run`. Its help identifies it as experimental/developer Linux/WSL tooling. **developer CLI != stable production CLI**. Production `Thiran` and its installed `thiran` name remain unchanged.

## Process, paths, and native strictness

The POSIX launcher uses `fork` + `execvp` with an argv vector and separate stdout/stderr pipes. It never uses `system()`, a shell command, or runtime shell parsing. CMake converts trusted build flags into configured argv elements, including sanitizer flags. Tests successfully checked source/output paths containing spaces and filenames containing `;` and `$()` as literal paths. Generated source and compiler artifacts use `mkdtemp` outside the checkout; only a successful final artifact is copied to the requested output.

The driver owns compiler executable, argv, include roots, V0 static archives, verified structured additional link items, and output path. The backend continues to own only extraction/emission. Build and run are STRICT_NATIVE and have no evaluator, legacy Graph, Python, PyTorch, NumPy, or Triton fallback. The host C++ compiler remains bootstrap build dependency. No cross-toolchain or Windows-host claim is made.

The development build record carries compiler stage, entry, coverage, optional retained source path, output artifact, and host compiler exit status. It is not a stable artifact/cache manifest.

## Buffer substrate and matrix

`storage::HostBuffer` shares TH-007 `StorageHandle` byte ownership but is a distinct C++ and semantic type with dtype and element count only. **Buffer != Tensor**: it has no shape, strides, rank, broadcasting, or matrix semantics. `Buffer<u8>` implements empty/materialized construction, exact length, checked reads, internal checked writes, ordinary shared alias, explicit deep copy, no COW, retained lifetime, and deterministic address-free storage debug identity. `MutableHostBufferRef` is move-only and requires an assumed prior TH-006 exclusivity proof. Handle count does not replace borrow proof; `ResourceId != StorageObjectId` remains true. No public source Buffer API was invented because the frozen source surface is insufficiently specified.

`V0BufferTests` covers BUF01–BUF15 directly: zero length, materialized bytes, length, reads/bounds, alias/copy, mutation visibility/isolation, no COW, retained handle, move-only mutable wrapper, checked byte arithmetic, deterministic identity, and Buffer/Tensor distinction/common storage machinery. BUF16 is the unchanged `V0OwnershipTests` Buffer access/resource regression, which also passed.

## Native-library contract and verifier

`thiran_v0_interop` defines internal contract ID, logical library/symbol, semantic parameter/result types, Read/MutableBorrow/Consume access, TH-006 effect set, may-trap flag, executable-support flag, host applicability, and structured StaticArchive/SharedLibraryName/SearchPath items. **native-library contract != arbitrary source FFI**. No `extern`, `unsafe`, raw pointer, `dlopen`, or arbitrary source library path was added.

The independent manual-metadata negative matrix rejects duplicate/empty IDs/names, empty or malformed symbols, invalid parameter/result types, scalar MutableBorrow, mutable access without Mutates, Mutates without compatible resource access, may-trap/effect disagreement, unknown effect bits, malformed link items, non-applicable host contracts at driver use, and unsupported executable results. Explicit effects are never inferred from symbol names.

The test-only static archive exports `thiran_test_add_i64`. A validated pure scalar contract supplies its archive through the structured link plan. The driver builds a C++ integration stub, a new process invokes the symbol, and stdout is exactly `42\n`. This proves the lower link boundary only; the symbol is not source-callable.
