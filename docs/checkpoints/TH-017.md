# TH-017 — Complete Reference-Model Deployment

Status: implemented; qualification evidence is captured by the repository test
matrix and must include an accessible physical CUDA device for PASS.

## Accepted lifecycle under test

The canonical test parses and analyzes one module containing the accepted
TH-011 affine loss and its inference entry. It creates the TH-011 plan with
trainable source indices `[3,2]` (`bias`, then `weight`), initializes both
parameters to zero, and performs 200 real TH-010/TH-011 full-batch SGD steps at
learning rate 0.02 on `x=[[0],[1],[2],[3]]` and
`target=[[1],[3],[5],[7]]`.

The resulting `TrainingState` is saved, its ordered parameter digest recorded,
and the original trained state destroyed before the canonical reload. The
restored state is compared representation-exactly, evaluated, and converted
through the checkpoint-only `DeploymentSnapshot` API. The bundle receives only
the restored frozen parameters and native artifacts; optimizer state and step
do not cross the deployment boundary.

The CPU artifact contains a planned/fused TH-016 ELF payload. The GPU artifact
contains persistent planned/fused PTX and executes with CUDA Driver JIT. The
model caller supplies only `x`; the runtime binds learned weight and bias by
`ParameterId`. Reference, CPU, and physical-GPU predictions are compared at
inputs 0, 1, 2, and 5.

## Qualification suites

```bash
./build/debug/v0_model_deployment_tests
./build/gpu/v0_model_gpu_integration_tests
```

The generic suite covers training quality and provenance, exact
destroy/reload, SGD and momentum resume equivalence, transactional save
failure, malformed checkpoint and bundle matrices, CPU-only explicit-backend
behavior, native CPU inference, and relocated fresh-process execution with
`PATH=/nonexistent` and `CXX=/nonexistent`.

The physical suite builds a dual-backend bundle from the same restored
checkpoint, checks CPU/GPU/reference equivalence, proves persistent PTX reuse
and CUDA Driver JIT, rejects invalid devices and CPU/GPU identity/signature
mismatches, observes TH-014 reservations through bundle destruction, and runs
both backends from a source/checkpoint/compiler-absent fresh directory.

The accepted qualification result is loss `84` to `1.44524392e-11`, learned
weight `2.00000167`, learned bias `0.999996901`, checkpoint step `200`, and
parameter digest `fnv1a64:06825ff73f4f2357`. Reference, CPU, and physical RTX 3050 Ti GPU
predictions agreed: `0 -> 0.999996901`, `1 -> 2.99999857`, `2 -> 5`, and
`5 -> 11.0000057`. The GPU evidence reported two kernels, one fused
group, one observation, all reservations released, no Thiran PTX generation at
execution, CUDA Driver JIT enabled, and no fallback.

## Deliberate limits

This checkpoint adds no training CLI, distributed or mixed-precision training,
general tensor input format, model registry, service, HTTP/gRPC layer,
container deployment workflow, framework runtime, Nerivu bridge, or
performance claim. FNV digests are integrity/identity evidence, not signatures
or authenticity guarantees. The reference model is intentionally small; the
checkpoint proves subsystem continuity rather than frontier model scale.
