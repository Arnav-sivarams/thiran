# TH-014 — asynchronous lifetimes

TH-014 adds a device-neutral outstanding-operation contract below the accepted structured semantic IR, TH-006 ownership/effect analysis, and TensorRegion layers. It does not add public syntax. `AsyncOperation` separates submission, pending execution, physical completion/failure, explicit observation, and reservation release. Runtime resources carry normalized read/write reservations rooted in physical storage identity; immutable aliases and views share conflicts, while explicit deep copies remain independent.

Pending GPU results are not `GpuValue`s. `submitNativeGpuAsync` returns a move-only `PendingGpuExecution`, an unobservable output resource with a write reservation, and submission evidence. `observe` synchronizes only its completion fence, reports deferred checked errors, materializes the host result, and releases reservations. `executeNativeGpu` remains source-compatible and is implemented by submit followed by observe.

The CUDA adapter uses the low-level dynamically loaded Driver API. Each pending execution retains its context, nonblocking stream, completion event, module, device allocations, input tensors, owned pageable-host upload/download staging, and checked-i64 error storage. Copies and kernels are enqueued in stream order; no per-kernel context synchronization remains. Pageable-memory behavior is not represented as proven overlap, and no performance claim is made.

Conflicting unordered reservations reject. Multiple independent operations and multiple immutable readers can remain pending. The conservative V0 dependency path narrowly observes declared predecessors before submitting a consumer; it never globally synchronizes unrelated work. Multiple producer/consumer kernels inside one TensorRegion are ordered on the same stream. A dropped handle safely drains without throwing, releases reservations, and records any deferred failure in the runtime unobserved-error channel.

The generic contract builds without CUDA. CUDA types and vocabulary remain confined to `NativeGpu.cpp`. The runtime API maps to the existing Transfer and Async effects instead of creating a second effect system. TH-006 source alias/move/view rules, TH-007 storage identity, checked i64/f32/shape/bounds behavior, and the no-fallback boundary are preserved.

Physical qualification used the NVIDIA GeForce RTX 3050 Ti Laptop GPU, driver API version 13030, compute capability 8.6. The async integration exercised f32 and i64 regions, three-kernel stream ordering, odd and zero sizes, aliases, independent copies/operations, concurrent reads, pending-output rejection, explicit observation, checked bounds/overflow, dropped deferred failure, invalid device/layout, and the synchronous wrapper. Final commands and aggregate suite results are recorded in the checkpoint handoff report rather than frozen into this specification.

Limits: no public async syntax, CPU async executor, cross-execution device-resident pending tensor, general cancellation, pinned-host allocator, async AD/training, allocator reuse, fusion, memory planning, global scheduling optimization, AOT/JIT artifact work, overlap claim, or benchmark is introduced.
