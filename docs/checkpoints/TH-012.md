# TH-012 — structured stateful scan

## Scope and representation

TH-012 adds a generic finite scan to the V0 typed structured semantic IR:

```text
scan(step, inputs, initial_state, captures...)
    -> (stacked_outputs, final_state)

step(input_element, current_state, captures...)
    -> (output_element, next_state)
```

The initial, current, next, and final states are ordinary typed semantic values. The step is one referenced semantic function whose body may contain existing structured control; its IR is not cloned per timestep. Inputs are traversed along their leading tensor extent in increasing order, output elements are stacked in that same order, and the scan remains visible as `Structured::Scan`. It is neither a legacy Graph/Region node nor a model-specific RNN/SSM operation.

The current reference subset accepts rank-one/rank-two i64/f32 input tensors. Rank-one inputs yield scalar step elements and rank-two inputs yield immutable rank-one logical elements. State supports i64/f32/bool scalars, rank-zero through rank-two i64/f32 tensors, and recursive tuples. Output elements are i64/f32 scalars or rank-one tensors; tensor output trailing extent is a statically known invariant contract.

Zero length invokes the step zero times, performs no step effect, produces a structurally typed empty output, and returns the initial state logically unchanged. Per-iteration type and shape checks reject dynamic contract changes. Checked failure stops immediately and publishes neither fabricated output nor final state. Existing resource-size and iteration guards enforce a finite bounded execution.

## Ownership and effects

The leading-axis element is a per-iteration immutable logical borrow. It may be read to compute output and state, but its resource may not escape through next state. Output stacking creates a fresh collection. Final-state provenance conservatively represents legal aliasing of initial state, captures, or a fresh next state. Scan introduces no implicit copy, move, copy-on-write, or hidden mutable state; existing explicit `copy`, explicit `move`, view-root, live-alias, and exclusive-mutation rules remain authoritative.

Step effects are included in the enclosing function summary. Pure and MayTrap steps are executable. Mutation, RNG, I/O, transfer, and async steps are rejected with `TH012-UNSUPPORTED-EFFECT`; zero-length execution does not run even a MayTrap step.

## AD and backend boundary

TH-010 has no executed-iteration save representation, reverse structured traversal, call differentiation, or stack/unstack adjoints. Differentiated scan therefore rejects explicitly with `AD-ELIGIBILITY-SCAN`. No hidden tape, numerical substitute, or framework autograd is introduced. Future recurrent AD must remain compiler-owned generated structured IR with explicit saved values.

TH-008 strict native compilation rejects scan as `BACKEND-UNSUPPORTED: Scan lowering deferred`, reports `Scan unsupported-native`, and records `fallback: NONE`. TH-012 adds no native or GPU execution.

## Current limits

The source spelling is an internal V0 intrinsic rather than a frozen public language API. Tuple output collection, input rank above two, output element rank above one, Buffer state, mutation/RNG/I/O/transfer/async steps, recurrent reverse AD, native CPU scan lowering, GPU scan, and physical buffer planning are deferred. Unsupported cases reject explicitly rather than weakening existing typing, ownership, effects, AD, or backend boundaries.
