## Parameter and state architecture

`ParameterId` is a deterministic plan identity derived from semantic FunctionId and source parameter index. It is distinct from BindingId, ValueId, ResourceId, StorageObjectId, handle, and address. The ordered descriptor retains source index/name, type, rank/shape fact, and plan position. Explicit request `[bias, weight]` is exercised so gradients, velocities, and updates cannot accidentally follow source or map/hash order.

`TrainingPlan` retains source semantic module, TH-006 ownership/effect facts, function identity, ordered runtime indices, ordered descriptors, `ReverseModeRequest`, generated forward/backward IR, generated ownership/effect facts, optimizer specification, deterministic plan signature, and developer-only generation count. Construction verifies semantic IR, runs ownership analysis/audit, validates scalar loss and explicit trainables/hyperparameters, differentiates once, audits AD, and analyzes/audits generated functions. Every step reuses the plan; parser, semantic analysis, and differentiation are not rerun.

`TrainingState` contains plan signature, step, ordered ParameterId/type/concrete-shape/value entries, and explicit `OptimizerState`. The state transition copies/builds complete new logical parameter values; the input state remains value/byte-equivalent under tests. Runtime inputs are separately indexed by source parameter index and assembled with parameters deterministically. Missing, duplicate, trainable-slot, type, rank, and concrete-shape errors reject before forward evaluation.

## One-step transaction and lifetime

`trainingStep` validates plan/state/inputs, invokes the TH-010 generated forward exactly once, retains scalar loss and explicit saves, invokes generated backward with `1.0f`, validates ParameterId/type/rank/shape for every ordered gradient, applies the optimizer into temporary complete vectors, increments state and optimizer step exactly once, and publishes one next state. Any forward, backward, gradient, or optimizer failure returns no successful next state. No parameter is updated piecemeal.

TH-010's forward tuple is the concrete SavedForBackward lifetime: it remains a live logical read alias until the matching synchronous backward completes, then the tuple is released before optimizer parameter replacement. Current parameter, saved primal, gradient, velocity, and optimizer result remain distinct concepts. No asynchronous backward or overlapping-step safety is claimed.

The loss and generated functions keep ordinary TH-006 Pure/MayTrap summaries. Reference training itself is documented as a runtime/library state transition, not Pure merely because it returns a new value. No fake source IO, RNG, or mutation effect was injected.

## Optimizers and independent validation

Plain SGD is exactly `p_next = p - learning_rate * gradient`. Momentum is exactly `v_next = momentum * v + gradient; p_next = p - learning_rate * v_next`, initialized with explicit zero-like velocity. There is no Nesterov, dampening, weight decay, clipping, loss scaling, or implicit cast. Learning rate is finite and nonnegative; momentum is finite in `[0,1)`. Binary32 helper arithmetic is kept in program order. IEEE gradient NaN/Inf is propagated rather than automatically rejected; zero learning rate remains legal.

## Linear-regression fixture and analytical result

The actual V0 source is the required four-parameter function using `x * weight + bias`, subtraction, elementwise square, and two explicit `sum(...,0)` reductions. Runtime batch and initial state were selected before qualification:

```text
x      = [[0], [1], [2], [3]]
target = [[1], [3], [5], [7]]
weight = [[0]]
bias   = [0]
plan trainable order = [bias, weight]
```

At step zero, predictions are all zero, errors are `[-1,-3,-5,-7]`, and loss is `1 + 9 + 25 + 49 = 84`. For squared-error sum:

```text
dL/db = 2 * sum(error) = 2 * (-16) = [-32]
dL/dw = 2 * sum(x * error)
       = 2 * (0*-1 + 1*-3 + 2*-5 + 3*-7)
       = 2 * (-34) = [[-68]]
```

The direct semantic evaluator loss, `TrainingStepResult.loss`, direct TH-010 grad, and training gradients agree. With SGD learning rate `0.02`, the independently calculated first update is bias `0 - .02*(-32) = 0.64`, weight `0 - .02*(-68) = 1.36`; observed values agree within `1e-5`.

The predeclared convergence configuration is learning rate `0.02`, 200 full-batch steps, and absolute tolerance `0.001` around weight 2/bias 1. Observed final loss was `1.44524e-11`, weight printed as `2`, and bias `0.999997`. Loss decreased by far more than the required factor. Two independent runs compared every loss bit pattern and final parameter/optimizer state exactly.

Momentum qualification used learning rate `0.01`, momentum `0.5`, and zero initial velocities. Step one matched plain SGD: velocities `[bias=-32, weight=-68]`, parameters `[bias=.32, weight=.68]`. At the second state, gradients were `[bias=-21.28, weight=-45.12]`; the hand transition gave velocities `[-37.28,-79.12]` and parameters `[.6928,1.4712]`, matching within `2e-5`. Repeated two-step execution was identical.
