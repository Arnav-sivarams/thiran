# TH-021 — Research extensibility / custom numerical operations

Status: implemented; pending architectural review before commit.

TH-021 introduces an explicit, frozen extension registry and an unstable V0
shared-library ABI for constrained elementwise f32 research operations. Normal
source calls resolve registered operations. Owned validated recipes flow
through semantics, TH-006 ownership/effects, reference execution, TH-010
reverse-mode generation, generic TensorRegion, TH-015 planning/fusion, native
CPU/PTX lowering, and TH-016 AOT/JIT identity.

The out-of-core fixture in `tests/fixtures/extensions/research_ops` declares
`research_square_linear`, `research_pair_mix`, a checked-ratio operation, and a CPU-only operation solely
through the public extension header. Production compiler code contains no
fixture-name dispatch. The main operation computes `x*x+x`; its declared
reverse recipe computes `dz*(2*x+1)` using an explicit saved `x`.

Qualification is provided by `V0ExtensionTests` and
`V0ExtensionGpuIntegrationTests`. They cover loader and transactional registry
failures, freeze, source errors, reference results, hand/finite-difference
gradients, save planning, structured control and forward Scan, CPU/GPU native
execution, fusion, AOT/JIT cache behavior, backend rejection, second-operation
genericity, and fresh-process artifact execution with no extension `.so`.

See `docs/spec/RESEARCH_EXTENSIONS_V0.md` for the contract and trust boundary.
