## Exact implemented subset

The differentiability predicate accepts f32 scalar and rank-one/rank-two f32 tensors. Bool, integers, Buffer, tuple output, other dtypes, and other ranks reject. Supported rules are Add, Subtract, scalar Multiply, tensor/scalar and elementwise Multiply, rank-two Matmul, rank-two Transpose, constant-axis Sum, trailing-axis broadcast reduction, and `stop_gradient`. Repeated uses accumulate through ordinary Add. Multiple WRT parameters preserve request order; an unused requested parameter emits ZeroLike.

Eligibility requires verifier-valid, import-free, straight-line IR, Read parameters, supported result and operations, and TH-006 Pure or Pure+MayTrap. Structured control, mutation/rebind, MutableBorrow/Consume, copy/move, index/slice, ordinary Call, imports, tuple output, and summaries containing Mutates/RNG/IO/Transfer/Async reject. Forward Checks remain ordered and a forward failure returns its original semantic error without executing backward.

## Forward, backward, saves, and helpers

Generated forward returns `(primal, saves...)`; generated backward takes flattened saves plus the explicit output cotangent and returns ordered requested cotangents. Names, FunctionIds, ValueIds, slot order, dumps, shapes, spans, and generated provenance are deterministic. The forward save-all baseline saves derivative operands and shape references plus requested inputs needed by ZeroLike. Metadata records primal ValueId, slot, type, shape, reason, provenance kind, and ResourceIds. Returned tuple elements alias retained logical values; no save inserts Copy or physical snapshot.

ZeroLike, ReduceToShape, and axis-aware BroadcastToShape are generated-only ordinary semantic operations with independent verifier and evaluator cases. ReduceToShape implements reverse trailing broadcasting, including tensor-to-scalar reduction and zero-size leading axes. BroadcastToShape inserts the axis removed by Sum. Matmul derivatives use ordinary Transpose and Matmul instructions.

Source `stop_gradient(expr)` is an intrinsic identity and retains alias/resource provenance; reverse traversal emits no input contribution. It never resolves as an ordinary Call. A dynamic `no_grad` context is deferred.

## f32 reference execution

The runtime represents f32 separately from i64 and executes scalar/tensor Add, Subtract, Multiply, ElementMultiply, rank-two Matmul/Transpose, constant-axis Sum, and trailing broadcast. It requires four-byte IEC 559 host float and active round-to-nearest. Matrix accumulation forces separately rounded float multiply and add; build flags use no fast-math and the evaluator performs no reassociation. Overflow/NaN/Inf follow IEEE behavior. Finite observations use `max_digits10`; NaN and infinities have deterministic spellings. This is a qualified host contract, not a universal future decimal serialization promise.

## Effect, ownership, native, and framework boundaries

TH-006 analysis runs on generated functions. Scalar arithmetic backward is Pure; helper/matmul shape obligations are MayTrap; no Mutates/RNG/IO/Transfer/Async effect is fabricated. Tensor saves retain original ResourceIds where available and the explicit forward tuple holds live read aliases. TH-010 does not claim mutation-versus-save safety outside its rejected mutating domain.

The TH-008 backend remains STRICT_NATIVE. f32 source passes semantic `check` but native build/extraction returns `BACKEND-UNSUPPORTED` with `fallback: NONE`; AD does not depend on or execute through the backend. No production CLI AD route was added. Source/dependency audits find no PyTorch, JAX, TensorFlow, autograd package, Python, NumPy, or Triton dependency in V0 AD.

## Limitations and handoff

TH-010 is first-order reverse mode. It does not implement a training loop, optimizer, final source grad API, forward mode, control-flow AD, differentiation through calls/imports/mutation/views/indexing/RNG/IO/Transfer/Async/native libraries, native f32/gradient lowering, custom derivative syntax, recomputation optimization, or higher-order differentiation. Generated backward being semantic IR does not imply grad-of-grad support.

A future custom-derivative contract must identify the primal operation/function, differentiable parameters, required saves, typed derivative computation, effects, and backend support. No Linear, Attention, Transformer, SSM, or Nerivu special case exists. TH-011 was not begun. Its handoff is to consume the explicit verified gradient IR and saved-value lifetime metadata without changing this reference-level contract.
