# TH-016 — real native AOT / JIT artifacts

TH-016 introduces the versioned `.tha` native container, typed entry ABI,
structural/integrity validation, deterministic inspection, native runtime
launcher, real CPU/GPU AOT paths, and explicit CPU/GPU JIT executable/cache
abstractions described by `docs/spec/NATIVE_ARTIFACTS_V0.md`.

CPU AOT stores a native ELF shared object and executes later through the small
native launcher/API without source, compiler, repository, Python, or framework
runtime. CPU JIT is accurately classified as external-native-toolchain JIT and
loads its generated shared object with `dlopen`/`dlsym`.

GPU AOT stores pre-generated fused PTX. Later execution validates and loads the
stored bytes through the CUDA Driver, whose device-load JIT produces device
code; Thiran PTX generation does not occur in that phase. GPU JIT instead runs
the Thiran PTX generator at JIT time and retains the resulting module payload in
an executable handle. Both use TH-014 submission/observation and TH-015 verified
planning/fusion, with no CPU/framework/reference fallback.

The in-memory specialization cache keys lowered computation identity, typed
shape/dtype signature, backend/target, ABI versions, and planner/fusion options.
The checkpoint tests cover relocation/fresh processes, compiler absence for
AOT, typed ABI failures, corruption/version/target rejection, checked i64 and
bounds failures, f32 behavior, zero-sized tensors, fused/unfused equivalence,
JIT compile/hit/miss evidence, resource cleanup, and physical GPU AOT/JIT.

This checkpoint adds substrate only. It does not add a model package, checkpoint
bundle, inference service, registry, remote cache, signing system, sandbox, or
TH-017 deployment workflow. Counts and artifact sizes are structural evidence,
not performance claims.
