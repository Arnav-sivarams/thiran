# TH-022 — Developer workflow / tooling

Status: implemented; pending architectural review before commit.

TH-022 consolidates the accepted V0 source, native CPU/GPU, TH-016 artifact,
TH-017 model, and TH-021 extension paths behind the production `thiran`
executable. The primary commands are `check`, `run`, `build`, `artifact`, and
`model`; the specialized artifact/model launchers remain thin supported
interfaces over the same libraries.

`run --backend cpu` and `run --backend gpu` lower through strict native
TensorRegion extraction, build a real temporary TH-016 artifact, and execute
that payload. The evaluator is not in either path, and GPU has no CPU fallback.
`build` writes ordinary `.tha` containers transactionally. Explicit TH-021
libraries feed the real frozen registry; their validated recipes are owned by
the artifact, so deployed execution remains plugin-free.

User diagnostics preserve semantic and ownership categories, render real
source spans with a source line/caret, support structured JSON records, use
conventional stdout/stderr separation, and have a small deterministic exit
contract. Command help, option ordering, extension identity listing, and
artifact inspection ordering are stable.

Qualification is provided by `V0WorkflowCliTests` and
`V0WorkflowGpuCliTests`. The CPU suite covers command parsing, paths with
spaces, missing/empty/malformed source, parse/semantic/ownership/extension
diagnostics, JSON diagnostics, native CPU source execution, CPU AOT,
inspection and execution, plugin-free extension artifacts, loader failures,
and artifact corruption/ABI failures. The GPU suite is a skip-77 physical
device test covering production-CLI source execution, persistent PTX build,
artifact execution, extension execution, plugin removal, invalid devices,
kernel evidence, and `fallback=NONE`.

See `docs/spec/TOOLING_V0.md` for the command and diagnostic contract.
