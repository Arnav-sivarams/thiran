## Syntax and resource semantics

Normal unqualified parameters are non-consuming Read; ordinary calls use f(A). Exceptional spelling is copy(expr), move(binding), and borrow mut binding at a call to a borrow mut Tensor/Buffer parameter. Scalar mutable-borrow parameters are rejected in this bounded resource-mutation subset. Explicit Consume parameters use move Tensor<T,R> and require move(A) at the call site. copy and move are reserved AST/IR primitives, not user functions. Expression statements allow standalone effectful calls. Bare shared borrow is intentionally absent.

ResourceId is deterministic logical mutable-resource identity, separate from BindingId and ValueId and unrelated to address, allocation, device buffer, or reference count. Fresh tensor-producing sites and parameters create IDs; ordinary aliases retain IDs; copy creates independent IDs with copy-source provenance; Move transfers an existing relationship while consuming only the source BindingId; arithmetic creates a fresh logical result. Tuples retain element provenance. Calls conservatively include possible argument aliases, caller view roots, and fresh logical results. This call-return overapproximation can reject a mutation that a future interprocedural return-provenance summary might prove legal; it never introduces a hidden copy.

Availability is DefinitelyAvailable, DefinitelyMoved, or MaybeUnavailable. A use requires definite availability. A type-compatible rebind of a mutable slot after Move reinitializes it. Rebind replaces one binding's logical value and does not mutate the old resource observed by surviving aliases. Copy is source-semantic independence; the reference evaluator can materialize it for observation. No physical allocator, tensor buffer, or copy-on-write path was introduced.

Slice, partial tensor indexing, and rank-two transpose are read views of a base ResourceId. ViewId, source span, and originating root BindingId are recorded. Moving or rebinding the actual root while a view may be live rejects; moving another alias of the same resource preserves the view rooted in its surviving alias. A view cannot be assigned into a longer-lived outer binding or returned. All view returns are deferred with TH006-VIEW-RETURN-DEFERRED until a truthful caller-root lifetime signature exists. A view from a temporary expression without a provable root handle is conservatively rejected.

## Liveness, branches, and loops

Backward may-liveness follows ordered steps. Writes kill the old binding value; if/else paths union, no-else retains the incoming path, Return terminates a path, and Break/Continue follow loop-exit/back-edge sets. Range and while loops solve deterministic may-live fixed points over a finite binding universe; an unresolved bound falls back to the full live universe. Forward resource/availability state merges paths conservatively. Returning paths are excluded from later source statements and retained for final fact inspection.

Loop head availability/resource state reaches a bounded fixed point across potentially repeated iterations. Failure to converge is a safety diagnostic, not an optimistic proof. While-condition ownership operations execute in the condition region on every iteration, including the first false condition; moves there flow to the successor and back-edge. A repeated move without definite reinitialization rejects. Constant source bounds are not used to fabricate one-iteration general legality.

At a borrow mut call, a live competing alias, view, overlapping call argument, unavailable source, or default Read parameter resource reached through a mutable local alias blocks exclusivity. Dead aliases/views do not. The borrow lasts only for the call; later ordinary reads are legal. A read view cannot grant MutableBorrow. A MutableBorrow parameter declares Mutates(parameter) even when no concrete indexed assignment exists. Forged IR that reuses or escapes a mutable-borrow instruction is rejected by an ownership IR audit before source facts are produced.

## Effects and future region boundary

The effect set represents Pure (zero), MayTrap, Mutates, RNG, IO, Transfer, and Async. Runtime Checks and possible checked i64 failures are MayTrap; a statically proven constant scalar arithmetic expression may be Pure. Copy is Pure for ordering while retaining ownership independence; Move changes binding state, not IO. Function effects union ordered nested-step effects and propagate callee effects through a deterministic recursive fixed point. Branch and loop summaries state possible effects without hoisting them from their execution paths. The pureTensorCandidate fact excludes any summary with MayTrap/mutation/future effects or any safety diagnostic; it is only a future extraction gate, not a compiled tensor region.

SavedForBackward and AsyncUsePending are documented future reservation extensions: a saved value is a live read obligation; pending device use remains a read/write obligation until completion. Neither is fabricated here. Future unsafe/FFI operations must declare ownership transfer, aliasing, extents, lifetime, device/thread requirements, and mutation. No unsafe source was introduced.

## Limitations and TH-007 handoff

TH-006 provides abstract source legality only. Mutable-borrow signatures may declare mutation, but indexed assignment and physical tensor content mutation are absent. Reference execution observes values using ordinary C++ containers, not aliasing pointers or runtime reference counts. Call-return resource provenance is conservative and may include possible argument aliases even for independently produced callee values; later interprocedural return contracts can refine it. Temporaries without a provable root cannot create escaping views. No struct/closure alias tracking, Buffer execution, returned-view lifetime signatures, unsafe FFI, AD save reservations, async GPU events, tensor-region extraction, physical layout/strides/storage, native execution, or device allocation is claimed.

The next checkpoint can consume ResourceId/view/liveness/effect facts when implementing its separately authorized storage/view boundary. TH-006 does not begin that work, alter the tensor DAG architecture, or commit/push/tag this result.
