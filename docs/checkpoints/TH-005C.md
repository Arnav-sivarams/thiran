## Representation decision

The TH-005 binding-to-current-ValueId map was straight-line only and could pick an arbitrary analysis-time value after a branch or loop. TH-005C introduces deterministic source-level BindingIds and retains ValueIds for expression results. `LoadBinding` reads the current logical value into a program-point ValueId; `BindingWrite` declares or rebinds the same logical BindingId. A rebind changes one binding's current value, not physical tensor storage. An immutable alias has a distinct BindingId but no semantic Copy/Move operation. Untaken branches retain the incoming slot value; loops carry slot transitions across iterations. This was chosen over immediate block-argument/join lowering because lexical identity and ordered transitions stay explicit for future path-sensitive ownership, executed-path AD, scan/recurrent reasoning, and tensor-region extraction. No storage identity, allocation, or reference count is implied.

Semantic `Block`s retain ordered steps and deterministic BlockId/parent BlockId, not raw parent pointers. `If`, `ForRange`, and `While` contain nested blocks/condition regions. Explicit `Flow` steps represent Return, Break, and Continue. Calls and tuples remain structured; checks retain their control region and order. The IR is source-semantic authority, not Graph/Region or backend jump code.

## Parser, analyzer, verifier, evaluator

The TH-004 reserved control keywords now have explicit spanned AST forms. Newline/semicolon blocks and tensor-row semicolons remain disambiguated by grammar. Range-for colon is scoped to `for`, distinct from annotations and tensor selectors. `for row in A` parses into a dedicated iterable form but receives deterministic `TH005C-ITERABLE-FOR-DEFERRED`; borrowed leading-axis tensor-view execution is not fabricated. Nested lexical shadowing is supported; duplicate same-block declarations, escaped branch locals, immutable/type-changing rebinds, non-bool conditions, non-i64 bounds, and out-of-loop controls are diagnosed at source spans. Unconditional same-block code after Return/Break/Continue is diagnosed `TH005-AFTER-RETURN`; no general reachability-warning pass is claimed.

Range bounds execute once and signed forward iteration is half-open. Equal/reversed bounds produce zero iterations; no unsigned wrap occurs. While condition IR is re-executed each iteration. Evaluator normal/Return/Break/Continue signals implement innermost-loop controls and whole-function early return. Its `TH005C-STEP-LIMIT` loop guard is internal developer tooling, not source-language semantics. Existing checked-i64 overflow, call-depth/step/tensor guards, and canonical observation remain.

The independent verifier checks region-local ValueId visibility, BindingId declarations/rebinds/induction contracts, BlockId ownership/parentage, bool conditions, i64 bounds, loop legality, Return type, structural completion, source provenance, instruction/check operand and shape/type contracts, and attachment of a trapping Check to its dependent operation in the same executing region. It does not call the analyzer.
