# TH-020 — Native GPU rendering / numerical interoperability

Status: implemented; qualification requires the physical GPU integration suite
in addition to CPU-only, regression, warning, and sanitizer evidence.

TH-020 extends the TH-019 numerical graphics contract with a real native CUDA
compute backend. Shared host code remains authoritative for validation,
model/view/projection transformation, six-plane clipping, deterministic fan
construction, viewport setup, degeneracy rejection, and orientation. A native
PTX kernel executes pixel coverage, top-left fill, strict depth selection, and
perspective-correct color interpolation physically on the GPU with one work
item per pixel and deterministic triangle order.

The GPU path reuses TH-013's dynamically loaded CUDA Driver substrate and
TH-014's reservation/observation lifecycle. The pending graphics handle owns
its packet, staging, context, module, stream, event, and RAII allocations until
observation or safe dropped-handle drain. GPU requests execute this path or
fail; there is no CPU renderer fallback.

Observation downloads color/depth and publishes fresh ordinary Tensor storage.
The qualified interoperability case feeds observed GPU color into the existing
native GPU TensorRegion executor. V0 performs D2H materialization after
graphics and a later H2D for that numerical execution. It is deliberately not
described as zero-copy, and no device-local graphics Tensor handle is exposed.

`V0GraphicsGpuTests` covers typed API selection, CPU-only unavailability,
validation-before-launch, PTX audit, and no-fallback behavior.
`V0GraphicsGpuIntegrationTests` physically covers single triangle, shared-edge
quad, near/far order independence, equal-depth first-wins, near-plane clipping,
perspective-correct color, non-power-of-two dimensions, the accepted 96x96
cube, repeated determinism, zero-size frames, invalid device, malformed PTX,
pending publication, normalized reservations, safe drop, independent pending
renders, CPU/GPU mask/value equivalence, and numerical Tensor interoperability.

The normative boundary is in `docs/spec/NATIVE_GPU_GRAPHICS_V0.md`; unchanged
graphics semantics remain in `docs/spec/GRAPHICS_V0.md`. This checkpoint adds
no external graphics API, framework, source syntax, artifact format, TH-018
work, TH-021 extensibility work, or performance claim.
