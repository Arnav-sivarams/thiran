# TH-015 — physical memory planning and kernel fusion

TH-015 adds a verified physical execution plan below `TensorRegion`. The plan separates logical `ValueId`/TH-006 provenance from physical slots, carries checked storage requirements and inclusive obligation lifetimes, assigns compatible non-interfering compiler temporaries deterministically, and exposes a stable diagnostic dump. Its independent verifier rejects malformed IDs, missing assignments, interference, capacity/layout/device errors, protected-root reuse, and invalid fusion groups.

The conservative reuse policy protects inputs, outputs, aliases/views, possible aliases, externally observed values, TH-010 saves, TH-011 parameters/state, and TH-014 reservations. Immutable aliases share root facts; explicit copies have independent roots. Completed-but-unobserved async work remains protected. Statically empty values have typed plan entries but no physical allocation.

Fusion is restricted to linear same-shape/same-dtype elementwise negate/add/subtract/multiply chains. Binding aliases can be traversed, but branches, extra consumers, copies, indexing, materialization/effect/observation barriers, structured control, and scan split groups. CPU lowering consumes slots as typed scratch vectors and emits one loop per group. GPU lowering consumes slots as per-execution device allocations and emits one PTX kernel per group. Checked i64 failure is retained at every operation and f32 operation order is unchanged.

The same backends accept a qualification option that disables reuse/fusion without creating a second implementation. Evidence reports logical/materialized intermediates, slots/reused assignments, groups/launches, and pending planner allocation retention. These counts describe the tested workload only and are not performance claims.

The legacy whole-program `Graph`, historical fusion rewrite, and historical `Region` planner remain outside V0 semantic authority. TH-016 artifact/cache/packaging infrastructure is not introduced.
